# Source data and trained planners

Reward choice shapes how AI social planners treat free-riders in simulated cooperation networks

Scope
This folder contains the existing numerical source records supporting the five main figures, four Extended Data figures and four Extended Data tables. figure_data_map.csv identifies the input files and existing processing functions for each display item. No training, simulation or scientific recalculation was performed to prepare this folder.

Files
- evals/: 21 original JSONL files, containing all 5,266 planner/condition/scenario-set evaluation records, copied without changes.
- evaluation_scalars.csv: the scalar fields of those same records exported as a spreadsheet-readable table; no new quantities are calculated. Nested trajectories, opportunities and recommendation/acceptance/change arrays remain in the JSONL files.
- paired.csv: objective values, held-out best-family selection, paired shortfalls, Monte Carlo standard errors, bootstrap intervals and normalized regret.
- marg_summary.csv and marg_ties.csv.gz: tie-value summaries and the deposited tie-level records.
- coef_draws.csv and coef_strata.csv: coefficient draws, one-step value curves and stratified diagnostics.
- calib.json and refcheck.json: stored human-comparison and independent-simulator checks.
- deltas.json: stored reference propensity shifts and reward scales used by the analysis.
- numbers_rev.json: existing manuscript summary statistics.
- run_manifest.csv: existing configuration and training manifest.
- training_logs.jsonl: configuration and log fields from all 592 ES and 124 PPO run files, collected without altering their numeric values. Complete run files and trained weights are included in runs_es/, runs_gnn/ and weights_gnn/.
- human_group_data/: three released group-outcome CSV files from McKee et al. (2023), https://osf.io/8ahkg/, CC BY 4.0. Group-level records, not new participant data.

Key fields
name identifies a trained or hand-specified planner. kind identifies its policy class; family identifies the objective/rule family. seed_train is the training seed. seed is the scenario-set seed: 12345 is reporting set A and 24680 is independent selection set B. train_cond and eval_cond distinguish training and evaluation conditions. n and n_games record sample sizes. Fields ending in _se are Monte Carlo standard errors, not training-seed standard deviations.

rec_rates, acc_rates, chg_rates and rec_opp retain the supplied array layout. Pair-type indices are 0 = DD, 1 = CD, 2 = CC; tie-status indices are 0 = absent/add and 1 = present/delete. Rates pooled over rounds, games or seeds must use opportunity weighting as implemented in analysis2.py and figs_rev.py. The paper states whether each uncertainty display uses seed s.d., a t-interval, seed range or bootstrap interval; do not substitute the _se fields for those displays.

Use and provenance
Most files are byte-identical copies of the confirmed research outputs. evaluation_scalars.csv and training_logs.jsonl change only storage format. These are underlying records, not an image-coordinate extraction. The public ../code/manuscript_stats.py computes the manuscript statistics from these records. figure_data_map.csv also records the original figure-processing function names from the accompanying Supplementary Software; those figure-layout scripts are not part of this core-code repository. The complete evaluation records are retained, including analyses not selected for formal display.

Human data retain their original CC BY 4.0 licence and attribution (see human_group_data/README.md). Scientific code is covered by the MIT licence in ../LICENSE.


## Trained planners

- runs_es/: 592 original run JSON files, including configurations, training logs and learned schedule parameters.
- runs_gnn/: 124 original PPO run JSON files, including configurations and training logs.
- weights_gnn/: 124 original PyTorch state dictionaries, matched to runs_gnn/ by filename stem.

The numerical files and model weights are unchanged copies of the confirmed research package. No training or simulation was repeated for this deposit. CHECKSUMS.sha256 records each deposited data file and its SHA-256 digest.

## Use with the public code

From the repository's code/ directory, after installing its requirements:

    python manuscript_stats.py ../data ../data/human_group_data ../outputs/statistics

To perform a new evaluation of the deposited trained planners (GPU recommended):

    python eval_all.py launch 1 0 ../outputs/evals ../data/runs_es ../data/runs_gnn

The repository includes stored evaluation summaries and trajectories, paired statistics, and tie-level records. The per-game arrays used to recompute paired bootstrap statistics are generated by eval_all.py; those temporary arrays are not included in the deposit. See the main README for seeds, sample sizes and paired-evaluation settings.
