# Scaffolding cooperation: reward design

[![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.23197614.svg)](https://doi.org/10.5281/zenodo.23197614)

Core experiment code for **Reward choice shapes how AI social planners treat free-riders in simulated cooperation networks**.

The repository contains a cooperative-network simulator, reward definitions, ES schedule optimization, graph-network PPO, common-scenario evaluation, paired statistics, mechanism checks and manuscript statistics. Four configuration lists specify 716 distinct runs: 592 ES and 124 PPO.

## Contents

- code/envtorch.py: game, fitted behaviour, acceptance and behavioural perturbations.
- code/rdp.py: rewards, policies, ES, per-component and joint-ratio PPO, evaluation.
- code/run_one.py and code/grid.py: individual training and GPU worker pools.
- code/configs/: original and revision configurations.
- code/make_configs.py: generator for revision configurations.
- code/eval_all.py and code/paired.py: common evaluation sets and paired shortfalls.
- code/propensity.py: reference intercept shifts and reward scales.
- code/marginal.py and code/coefprop.py: tie values and coefficient uncertainty.
- code/sim_numpy.py, code/calib.py and code/refcheck.py: independent simulator and checks.
- code/manuscript_stats.py: seed summaries, opportunity-weighted phase rates, frozen transfer, ES–GNN agreement, regret and objective compatibility, human calibration errors and optimization comparisons.
- inputs/deltas.json: necessary reference input for configurations containing symbolic intercept shifts or penalty scales. Copied from the supplied revision package; generated by propensity.py.

Generated results, trained weights, human outcome data, figures, plotting scripts and manuscript files are excluded from this minimal release. Training inputs are included. Simulating the calibration conditions requires no human data; comparison with human group outcomes additionally requires the released summaries at [OSF](https://osf.io/8ahkg/), licensed CC BY 4.0.

## Environment

Original experiments: Python 3.11, PyTorch 2.0.1 with CUDA 11.8 and NumPy 1.26 on NVIDIA H20 GPUs.
CPU checks and formal marginal recomputation: Python 3.12.4, PyTorch 2.9.1, NumPy 1.26.4, pandas 3.0.2 and SciPy 1.13.1 on Windows.

Create a separate environment and activate it before installing dependencies:

    python -m venv .venv
    python -m pip install -r requirements.txt

Windows activation: .\.venv\Scripts\Activate.ps1. Linux/macOS: source .venv/bin/activate.
For GPU training, install a PyTorch build compatible with your CUDA environment.

Run the following commands from code/. Paths are relative to that directory.

## Small execution example

PowerShell 7 (tested with version 7.6.6):

    cd code
    $cfg = @{name="demo_es"; policy="table"; obj="coop_mean"; kappa=1.0; seed=0; iters=2; npair=2; games=2; eval_games=16} | ConvertTo-Json -Compress
    python run_one.py $cfg ../outputs/demo

Linux/macOS:

    cd code
    python run_one.py '{"name":"demo_es","policy":"table","obj":"coop_mean","kappa":1.0,"seed":0,"iters":2,"npair":2,"games":2,"eval_games":16}' ../outputs/demo

This reduced example checks execution; it does not reproduce a manuscript training run. Outputs are per-run JSON (configuration, log, evaluation and schedule table) and a PyTorch state dictionary.

## Re-running experiments

Full grids require substantial GPU computation. These commands preserve the supplied scientific settings:

    python grid.py configs/configs_es.json 1 0 ../inputs/deltas.json ../outputs/runs_es
    python grid.py configs/configs_es2.json 1 0 ../inputs/deltas.json ../outputs/runs_es
    python grid.py configs/configs_gnn.json 1 0 ../inputs/deltas.json ../outputs/runs_gnn
    python grid.py configs/configs_gnn2.json 1 0 ../inputs/deltas.json ../outputs/runs_gnn
    python eval_all.py launch 1 0 ../outputs/evals ../outputs/runs_es ../outputs/runs_gnn
    python paired.py ../outputs/evals ../outputs/paired.csv

Worker counts and GPU identifiers are execution options. Keep the configuration files for model parameters, objectives, optimizer settings and seeds. ES uses 400 iterations, 256 antithetic pairs and 32 games per perturbation; PPO uses 600 iterations, 8,192 games per iteration, two epochs and 16 minibatches.

Evaluation uses reporting set A (seed 12345) and independent selection set B (24680): 20,000 games for own-condition evaluations and 10,000 for frozen-policy transfer. Seed-A per-game arrays are generated locally for paired statistics. Small checks can override RDP_N_OWN and RDP_N_CROSS; restore defaults for manuscript experiments.

Additional calculations:

    python propensity.py ../outputs/deltas_regenerated.json
    python marginal.py ../outputs/runs_es ../outputs/marg 20000
    python coefprop.py ../outputs/coef 20000 1000
    python calib.py ../inputs/deltas.json ../outputs/calib.json 8000
    python refcheck.py ../outputs/refcheck.json 8000

make_configs.py writes revision lists to its current directory. Run python ../make_configs.py from code/configs/ to regenerate them separately.

## Manuscript statistics

After generating the evaluation, paired and calibration outputs above, download the three released human group-outcome CSVs from [McKee et al.'s OSF repository](https://osf.io/8ahkg/) into a local data_osf/ directory. The expected inputs are:

    outputs/evals/evals_*.jsonl
    outputs/paired.csv
    outputs/calib.json
    data_osf/baseline_group_outcomes_data.csv
    data_osf/evaluation_group_outcomes_data.csv
    data_osf/validation_group_outcomes_data.csv

From code/, run:

    python manuscript_stats.py ../outputs ../data_osf ../outputs/statistics

The same command accepts results/ and data_osf/ from the separate submission package. Use its corrected paired.csv, or regenerate paired.csv with this release before analysing historical outputs.

Outputs are numbers_rev.json (seed means and standard deviations, weighted recommendation/change rates, transfers, ES–GNN correlations and errors, regret and objective compatibility), calibration_mae.csv (final-cooperation mean absolute error over five human comparison conditions), and best_found_k0.5.csv (optimization comparisons). Statistics use reporting scenario set A; set B retains its separate role in selecting the best planner in paired.py.

These calculations were extracted from the supplied analysis2.py, stats_rev.py, figs_rev.py and make_figures.py without changing their scientific definitions. No plotting library is required. Regenerating the statistics from all 5,266 supplied evaluation records reproduces the deposited number file, with the previously authorized same-family interval corrections, and both original comparison-table calculations. This verifies the analysis of stored records; it does not constitute a new training or simulation replication.

## Reproducibility and scope

Training is seeded; different hardware or software can produce different trained planners. Evaluation is repeatable for a fixed planner, condition, seed, batch size and environment. Use the same batch size (4,000 in the supplied protocol) across planners for paired differences.

Game, rewards, optimizers, configurations and seeds are preserved. Packaging fixes protect Windows multiprocessing entry points, release locks after normal completion or Python exceptions, and recognize GNN weights in weights_gnn/ as well as beside run JSON files. Forced process termination may leave a stale lock; verify the worker has stopped before removing it.

The historical baseline-only runner is omitted; use eval_all.py. Stored outputs and figure-generation code remain in the separate submission package. This repository generates the manuscript statistics from the specified inputs; generating the formatted manuscript figures additionally requires the separate figure scripts. Deposited results and trained weights are not yet available through a public archive linked from this repository; this is a core-code release.

The tie-value calculation follows the manuscript: a 0.005 grid over 0–1.5 and 2,000 bootstrap resamples for break-even intervals. The first transition from negative to non-negative mean value is interpolated; a value already non-negative at kappa = 0 has break-even 0. Coefficient uncertainty retains its existing 0.005 grid. Same-family shortfall confidence intervals are zero; other family comparisons retain the supplied bootstrap draws.

These statistical corrections were made after auditing the authors' revision package. On 7 October 2026, all 36 marginal-analysis conditions were recomputed with the unchanged archived marginal.py: 20,000 games per condition, the 0.005 grid over 0-1.5 and 2,000 bootstrap resamples. The separate submission package and affected figures/text have been refreshed; these generated results are not included in this core-code repository. CPU and GPU random streams differ, so point estimates as well as intervals were reconciled. Full training has not been re-run. The fixed v1.0.0 software archive is unchanged.
